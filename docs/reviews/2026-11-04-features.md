## Summary
Adds the first FastAPI surface: app factory, pure ASGI request-context and body-limit middleware, RFC 9457 problem rendering, settings, JSON logging, and one stateless summary endpoint wrapping the unchanged Phase 1 domain. Implementation matches spec 0008 closely. I re-ran the suite (516 pass), Ruff and Pyright (clean), and probed edge cases (datetime min/max, large decimals, BOM, deep nesting, unknown keys, HEAD/OPTIONS, CORS); none produced a 500 or a wrong number. No blockers or majors; the findings are small leaks, a logging noise issue, and test hygiene.

## Minor
### 🟡 Validation errors echo client-supplied key names, `backend/src/energyiq/platform/http/problems.py:547`
**Problem**: `loc` is copied from Pydantic. For `extra_forbidden` the last `loc` element is the submitted key, so a body with `"john.doe@example.com": 1` returns that string in `errors[].loc` (verified).
**Why it matters**: Spec AC-8 says problem bodies "never echo the submitted value". Keys are client controlled text and can carry personal data; once this is reused on persisted/authenticated routes the claim is false. Bounded by the body cap, so no amplification.
**Suggested fix**: For `unknown_field`, replace the final `loc` element with a fixed placeholder (or drop it), and add a test asserting the key text is absent from the response.

### 🟡 Mid-stream failure produces an unattributed uvicorn error, `backend/src/energyiq/platform/http/middleware.py:277`
**Problem**: After the response started, the middleware logs the traceback and returns without completing the ASGI response. uvicorn then logs "ASGI callable returned without completing response" with no request id (your observation (a), confirmed by reading the code path).
**Why it matters**: One incident yields two log entries, the second not correlatable. No current route streams, so impact is latent.
**Suggested fix**: Accept and document it, or re-raise after logging only in the response-started case and make the error logger the single source. Do not send a closing body message (it would make a truncated response look complete).

### 🟡 Default `ENERGYIQ_ENV=dev` fails open, `backend/src/energyiq/platform/settings.py:176`
**Problem**: With no env var set, docs, `/openapi.json` and the localhost CORS origin are enabled.
**Why it matters**: A production deploy that forgets the variable exposes docs and a dev CORS origin silently. The spec chose this default; the security cost is small today (no data, no auth) but grows at P2-03.
**Suggested fix**: Revisit at P2-03 (default to prod or require the variable); note it in the spec follow-ups.

### 🟡 Logger-level restore not exception safe, `backend/tests/api/test_middleware.py:418`
**Problem**: `test_access_line_written_at_warning_level` restores INFO by calling `create_app` as its last line. If an assert fails, the global `energyiq` logger stays at WARNING for later tests.
**Why it matters**: A single failure cascades into unrelated failures that look like missing logs (global state in a process-wide logger, `propagate=False`).
**Suggested fix**: Restore in a fixture or `try/finally` (or an autouse fixture that resets level and removes extra handlers).

### 🟡 Live-server test can hang or leak on teardown, `backend/tests/api/test_live_server.py:266`
**Problem**: `process.wait(timeout=10)` raising `TimeoutExpired` skips `log.close()` and leaves the child; the free-port helper has a bind race; `httpx2.get` honors proxy env vars.
**Why it matters**: Low probability flakiness on CI or a dev machine with proxy settings.
**Suggested fix**: `process.kill()` fallback in `finally`, `trust_env=False` on the client, and close the log file in its own `finally`.

## Nits
- ⚪ `backend/src/energyiq/platform/http/middleware.py:269`, `MutableHeaders(scope=message)` raises `KeyError` if a downstream app omits `headers` on `http.response.start` (legal in ASGI). Use `message.setdefault("headers", [])` first.
- ⚪ `backend/src/energyiq/platform/http/middleware.py:252`, status defaults to 500, so a `CancelledError` (BaseException, not caught) logs an access line with status 500 although nothing was sent.
- ⚪ `backend/src/energyiq/platform/http/types.py:149`, `datetime.fromisoformat` also accepts a space separator, ISO week dates and compact forms; fine, but the message and docs say "ISO 8601" without noting the leniency.
- ⚪ `backend/src/energyiq/main.py:36`, `_problem_media_types` iterates every value of a path item; a path-level `parameters` list would break it. Not emitted by FastAPI today.
- ⚪ Observation (b), prod OPTIONS preflight gets a 405 problem: correct (no CORS headers is the intended "off" behavior) and documented; no action.
- ⚪ CORS rejection (plain 400) and `Allow`-less responses sit outside the problem shape by documented exception.

## Strengths
- Middleware is genuinely careful: single 500 path with one traceback and request id, disconnect suppression yielding 499, request id validated with `fullmatch`, streamed 413 raised as `HTTPException` so FastAPI does not downgrade it to 400.
- Output formatting is owned by the API (`format(value, "f")`, fixed UTC and duration renderers); datetime parsing rejects numbers and naive/overflowing values; extreme dates and 12.6 digit sums computed correctly in my probes.
- Logs carry route templates only (no query, headers, body, client address); tests assert it.
- Strong test suite: ASGI-level tests for headers, chunking and disconnects, OpenAPI snapshot, import-boundary test, live uvicorn smoke, idempotent logging.

## Test coverage

Gaps: no test that unknown field names are not echoed, no test of the `headers`-less start message, and the global logger state handling in tests (see Minor).
