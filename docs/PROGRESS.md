## Known gaps and constraints

- Consumption requires Decimal inputs, including for whole numbers. The arithmetic policy uses precision 28, `Emin=-999999`, and `Emax=999999`, and rejects numeric rounding, overflow, and underflow. Exact subnormal values are allowed. P1-01 defines a separate reading scale of six meaningful fractional places and a maximum of `999999999999.999999` kWh. Elapsed hours retain float approximation.
- Source execution requires `backend/src` on `PYTHONPATH`; no distributable build or installed CLI command is configured. README documents invocation using the existing local environment.
- Previous Windows pytest cache write warnings were avoided by disabling the optional cache provider for that invocation; no filesystem repair was made.
- Git is available on branch `features`. On 2026-11-03, `git fetch --quiet` succeeded and `git rev-list --count HEAD..origin/main` returned one. The remote commit merges earlier Phase 0 work; this branch contains P1-01. Existing changes in `.gitignore`, `.idea/`, and `skills-lock.json` are outside this task. No commit was requested or made.
- Spec 0001 exists locally but is ignored by the existing `.gitignore` rule `/docs` at line 21. Already tracked documentation remains tracked. The ignore rule was not changed, and the spec was not staged. No scope directory exists; the four build tasks remain in the spec and their completion is recorded in the delivery row above.
- Spec 0002 is also ignored by that existing `/docs` rule. It needs explicit force staging when committing P1-01, without changing the unrelated ignore rule.

- Spec 0004 is also ignored by `/docs` and needs explicit force staging when committing P1-03. No scope directory exists; its build tasks stay in the spec.
- Links that predate P1-06 in `README.md`, `docs/04-DATA-MODEL-API.md`, the roadmap, and this file point to specs 0001 to 0004, `docs/tasks/`, `docs/reviews/2026-11-03-features-p1-02.md`, and `docs/archive/PROGRESS-MENTORSHIP.md`, which commit `54143f5` removed from the working tree. They do not resolve. Spec 0007 AC-1 limits its link check to links added or edited in P1-06, so these are a known gap, not a P1-06 failure.
- Observation sorting preserves duplicates and accepts typed kWh values without validating them; it does not resolve discontinuities, calculate intervals, or enforce meter ownership. It performs no data access. Callers must supply observations for one meter; Phase 1 adds domain models and duplicate/continuity enforcement.
- P1-01 models validate individual records only. P1-02 reports duplicate timestamps. P1-03 rejects conflicts, computes valid intervals, and reports invalid pairs, but does not reconcile conflicts, change reading status, approve events, calculate daily rates, or characterize coverage. P1-04 adds rates and window coverage but never estimates: a window edge that cuts a valid interval drops that interval's kWh and reports a `partial_interval` gap. Calendar day allocation is left to a later presentation spec. Date only readings are converted to 12:00 `America/Santo_Domingo` (16:00 UTC) at the P2-04 API boundary, as decided in P1-06; until then the domain only accepts exact UTC instants and `original_local_date` is provenance only. Rollover kWh stays unsupported until the Meter stores a register digit count (Phase 2).
- Verification used synthetic fixtures and no external services, personal data, or new dependencies. Sandbox command startup still failed, so local checks used approved execution outside the sandbox. No deployment or application write action was performed.

- Windows has no IANA time zone database: `ZoneInfo("America/Santo_Domingo")` raised `ZoneInfoNotFoundError` in the project environment (found 2026-11-03 during P1-06). Resolved 2026-11-04: P2-02 added `tzdata` 2026.6 as a runtime dependency for P2-04's date only conversion.
- Integration tests need the Compose database (`docker compose -f infra/compose.yaml up -d db`). Without it the `db` tests skip; set `ENERGYIQ_REQUIRE_DB=1` to make that a failure. The Windows host takes about 2 s to refuse a connection to a closed local port, which is the readiness worst case.
